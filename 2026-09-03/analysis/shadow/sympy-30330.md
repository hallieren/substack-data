## What changed

In `modified_subresultants_pg`, a zero pseudo-remainder means the sequence has terminated, so the Pell–Gordon sign/degree-update logic should not be run (it would introduce infinities/`nan` and crash on `sign(nan)`).

- **First remainder step:** after computing `a2 = -rem(a0, a1, ...)`, if `a2 == 0`, return the sequence `[p, q]` immediately instead of proceeding with PG updates.
- **Main loop:** after computing each new remainder, if `a2 == 0`, `break` out of the loop instead of performing PG updates or appending a zero remainder.

## Verification

The reported examples now match `sympy.polys.polytools.subresultants`:

```python
subresultants_pg(4*x**3 + 3*x**2 + x + 2, x + 1, x)
# [4*x**3 + 3*x**2 + x + 2, x + 1]

modified_subresultants_pg(4*x**3 + 3*x**2 + x + 2, x + 1, x)
# [4*x**3 + 3*x**2 + x + 2, x + 1]

subresultants_pg(x**4 - 1, x**2 - 1, x)
# [x**4 - 1, x**2 - 1]
```

Also verified later-termination cases such as `subresultants_pg(x**4 + x**3 + x + 1, x**2 - 1, x)` no longer crash and agree with the corresponding AMV/polytools implementations.
