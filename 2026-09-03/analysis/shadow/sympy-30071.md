## pico's final report

Implemented the fix in `sympy/integrals/manualintegrate.py`.

## What changed

The manual integrator already had a `trig_cmplx_exp_rule` that rewrites products containing `sin`, `cos`, `sinh`, `cosh` into complex exponentials when that rewriting is helpful. However, it only activated when the original integrand already contained a Gaussian exponential like `exp(a*x**2 + b*x + c)` (or the special `trig*exp/x` form).

The integrand

```python
exp(x)*sin(x**2 + x)*cos(x)
```

contains only a linear `exp(x)`, so the rule did not fire. The integrator then fell through to integration-by-parts heuristics, which recurse extremely deeply and hang instead of giving up.

I extended the rule to also activate when the integrand has an exponential factor together with a trig/hyperbolic function whose argument is a quadratic polynomial in the integration variable. Rewriting such trig terms produces Gaussian complex exponentials (e.g. `exp(I*x**2 + ...)`), which the existing special-function machinery can integrate via `erf`/`erfi`.

## Verification

The previously hanging case now completes:

```python
integrate(exp(x)*sin(x**2 + x)*cos(x), x)
```

returns an antiderivative containing `erfi` terms instead of hanging, and its derivative matches the integrand numerically/after simplification.
