## pico's final report

Implemented the fix in `sympy/series/limits.py`.

The problem was that `Limit.pow_heuristics()` internally computed limits without passing along the one-sided direction (`dir`). For example, for `2**(1/x)` with `x -> 0-`, it called `limit(log(2)/x, x, 0)` with the default direction `'+'`, incorrectly producing `+oo`, so `exp(+oo)` gave `oo` instead of `0`.

Changes made:
- Added a `dir` parameter to `Limit.pow_heuristics()`.
- Passed that direction through to every internal `limit()` call in the heuristic:
  - `limit(e1*log(b1), z, z0, dir)`
  - `limit(e1, z, z0, dir)`
  - `limit(b1, z, z0, dir)`
  - `limit(e1*(b1 - 1), z, z0, dir)`
- Updated the call site in `Limit.doit()` to pass the current `dir`.

Verified:
- `limit(2**(1/x), x, 0, dir='-')` now returns `0`
- `limit(2**(1/x), x, 0, dir='+')` still returns `oo`
- `limit(2**x, x, -oo)` returns `0`
- Full `sympy/series/tests` suite passes (475 passed, no regressions).
